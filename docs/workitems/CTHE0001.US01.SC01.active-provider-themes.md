## Outcome

Optional active theme plugins participate in the real Components provider resolver.

## Implementation boundary

Bridge Plugins theme identities to the actual Components resolver in an optional integration layer. Preserve the current non-plugin mode, provider state, consumer class/fragment precedence and theme-style family boundaries.

## Acceptance criteria

- [ ] UAC01: Given two independent ThemeProviders and an active theme plugin, when classes/fragments/style families resolve, only the selected provider changes and explicit consumer overrides retain their existing precedence.
- [ ] UAC02: Given an inactive or invalid theme binding, when theme enumeration/resolution occurs, it is excluded or rejected before publication without changing the current provider selections.
- [ ] UAC03: Given a selected plugin theme in a published package consumer, when its owner withdraws, subsequent renders restore host defaults and detach plugin stylesheet selection while unrelated provider state and already deployed public files remain intact.
