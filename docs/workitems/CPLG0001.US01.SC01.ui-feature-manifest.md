## Implementation

The implementation phase covered the smallest behavior the three criteria
assert:

- `src/core/` owns the shared component contracts: the startup binding, the
  startup registration, the trusted startup map, the feature manifest, the
  activation result and error types, and the activator itself. `src/core` keeps
  no host-framework dependency.
- `src/lib/ComponentsControlsStartup.cs` and `src/blocks/ComponentsBlocksStartup.cs`
  register the logical key each base library owns, so a feature can declare a
  logical dependency on it. `src/core/ComponentsCoreStartup.cs` does the same
  for the Core package. A base library registers a key only; it carries no
  manifest and stays an ordinary dependency.
- `src/features/LowlandTech.Components.Features.Session/` publishes the
  manifest and the startup binding of the opt-in feature. The package contains
  no component of its own: the session surface stays in the base Blocks
  package, and the feature package depends on it as an ordinary NuGet
  dependency.
- The activator is a pure decision. It reads the manifest, the startup map and
  the deployed feature keys, and reports the outcome; it never changes the
  host project, the deployment snapshot or the startup map.

## Implementation boundary

Choose one small existing Components feature and declare its stable logical plugin key, versioned manifest, symbolic contribution identities, logical dependencies and trusted startup bindings in an opt-in package. Keep NuGet identity distinct. Do not make every base control a plugin.

The implementation owns the opt-in feature package with its published
manifest, the Components feature activation contracts and the startup
registration of the feature. It does not own the host-side projection of
active panels, blocks, themes or pages (CPAN0001, CBLK0001, CTHE0001,
CPGS0001), the Plugins runtime (the Plugins repository), the installation and
deployment adapters of a host (Plugins and Coder), or any change to the public
contracts of the base packages.

The projection of an installed manifest onto the Components activation
descriptor belongs to the host adapters, which map the parsed Plugins manifest
the host already owns. This scope publishes the manifest and the contracts; it
does not fork the Plugins manifest schema.
