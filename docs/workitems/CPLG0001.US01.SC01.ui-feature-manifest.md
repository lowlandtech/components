## Refinement

**Chosen feature.** The session plugin surface of Components — the session
plugin host and the session panels it renders, owned today by
`src/blocks/Session` (`SessionPluginHost.razor`, `SessionPluginRegistry.cs`,
`SessionPluginModels.cs`). It is small, it already exists and it is Blazor only.
The projection of an installed panel into a host surface belongs to CPAN0001 and
is not part of this scope.

**Opt-in package.** A new packable project at
`src/features/LowlandTech.Components.Features.Session/`, published as
`LowlandTech.Components.Features.Session`. The NuGet identity stays distinct
from the base packages: `LowlandTech.Components.Core`,
`LowlandTech.Components` and `LowlandTech.Components.Blocks` stay ordinary
dependencies and carry no manifest.

**Published manifest.** One `lowlandtech/plugin.json` at the canonical archive
path inside the feature package, schema version 2:

| Declaration | Value |
|---|---|
| `key` | `lowlandtech.components.session` |
| `target` | `blazor` |
| `installationUnit.requiredCapabilities` | `["blazor"]` |
| `dependencies[0].key` | `lowlandtech.components.blocks` |
| `contributions.components` | `LowlandTech.Components.Blocks.Session.SessionPluginHost` |

**Trusted startup bindings.** The host registers the logical keys the base
libraries own (`lowlandtech.components.core`, `lowlandtech.components.controls`,
`lowlandtech.components.blocks`) and the feature registers its own logical key
together with the symbolic identity of the contributed component. The startup
map is the only place a symbolic identity becomes a CLR type; nothing is loaded
at runtime.

## Implementation boundary

Choose one small existing Components feature and declare its stable logical plugin key, versioned manifest, symbolic contribution identities, logical dependencies and trusted startup bindings in an opt-in package. Keep NuGet identity distinct. Do not make every base control a plugin.

The execution phase owns the opt-in feature package with its published
manifest, the Components feature activation contracts named above and the
startup registration of the feature. It does not own the host-side projection
of active panels, blocks, themes or pages (CPAN0001, CBLK0001, CTHE0001,
CPGS0001), the Plugins runtime (the Plugins repository), the installation and
deployment adapters of a host (Plugins and Coder), or any change to the public
contracts of the base packages.

## Acceptance criteria

- [ ] UAC01: Given locally packed feature and base packages, when Plugins inspects them, the feature has exactly one valid lowlandtech/plugin.json with target blazor and base libraries remain ordinary dependencies.
- [ ] UAC02: Given an explicit compatible deployed host, when the feature activates, its declared component resolves through a trusted startup map; inactive or undeclared components do not resolve.
- [ ] UAC03: Given a backend-only target or a missing logical dependency, when feature installation/activation is validated, it fails by name without project/snapshot mutation; a missing deployment reports rebuild/restart.
