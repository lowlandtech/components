## Outcome

Components hosts expose plugin pages and navigation only while their owner is active.

## Implementation boundary

Use existing Plugins route/page primitives and trusted startup component maps. Preserve base app routes. Adapt real PluginPage metadata without treating a loaded assembly or AdditionalAssemblies membership as authorization.

## Acceptance criteria

- [ ] UAC01: Given a deployed active page with metadata, when navigation and direct routing are evaluated, label/group/order/hidden-navigation behavior is preserved and host authorization runs before protected content/actions.
- [ ] UAC02: Given conflicting routes or invalid component metadata, when activation is validated, it fails by name before replacing the previously valid route/navigation projection.
- [ ] UAC03: Given a discovered page and retained URL, when its owner withdraws, subsequent navigation and direct route resolution are denied or reach host fallback; a stale browser projection cannot authorize server data/actions.

## Consumer integration boundary

Coder M6-011 consumes this page adapter through the shell route gateway. Expose
trusted metadata/registration without a dependency on Coder or the demo Router.
Verify an Interactive Server RCL consumer, including reserved host routes and
guarded retained URLs. WASM projection remains a separate integration mode.
