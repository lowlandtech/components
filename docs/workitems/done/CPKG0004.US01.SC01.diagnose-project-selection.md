## Outcome

A caller that selects a subset of projects for the packing tool either binds the
selection it meant or is refused with one diagnostic that names the supported
invocation. A malformed selection never reaches the build with a message about a
missing file, and the supported invocation keeps packing exactly the selected
projects.

## The request

- `20261029T234545772393Z-aee0a1fd@coordinator-1` asks for this as separate
  Components-owned tooling scope: a documented selected-project invocation must bind
  multiple projects as intended, while malformed or ambiguous input refuses with a
  named diagnostic;
- `20261029T113848893046Z-60b4cf6b@coordinator-1` asks to keep the exact invocation
  and the observed binding;
- the lane met the defect twice while packing a subset: in `CPKG0002` and in the
  measurement of `M7-001`.

## The measured binding

| Invocation | Observed binding | Outcome |
|---|---|---|
| `pwsh -NoProfile -Command "& eng/build-local.ps1 -Projects @('a','b')"` | `$Projects.Count = 2` | the supported shape; it packs the two projects |
| `pwsh -NoProfile -File eng/build-local.ps1 -Projects @('a','b')` | `$Projects.Count = 1` with `a`, and `b` as a stray positional | `A positional parameter cannot be found that accepts argument 'b'` |
| `pwsh -NoProfile -File eng/build-local.ps1 -Projects 'a,b'` | `$Projects.Count = 1` with `a,b` | a later `Missing build input` for a path that never existed |

## Acceptance

- [x] UAC01: Given a selection that reaches the tool as one comma-joined string, when the tool runs, then it refuses with one diagnostic that names the supported array invocation and packs nothing.
- [x] UAC02: Given a selection that leaves a project as an unbound positional argument, when the tool runs, then it refuses with the same named diagnostic instead of reporting a positional binding error.
- [x] UAC03: Given the supported invocation with two selected projects, when the tool packs, then it publishes exactly those two packages.
- [x] UAC04: Given two batches of different versions started at the same time, when both run, then both publish and neither reports the IO error of a shared build output.

## Boundaries

- This scope changes the argument diagnosis of the packing tool only. It does not
  change the manifest, the version prefix, the declaration of the dependency range or
  the publication path.
- No package is published by this scope.
