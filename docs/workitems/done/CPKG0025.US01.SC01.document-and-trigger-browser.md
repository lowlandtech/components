## Outcome

The document view and the action trigger are observed in a real browser — labels, read-only
values, relations, an action that runs, a refusal, a conflict and the keyboard result — against a
test-owned host with a dedicated Chromium, so focus and announcement are proven rather than
asserted in a unit test.

## Refinement decisions (2026-11-26)

- **The lane's own e2e project and pattern**: `src/e2e` (xUnit v3 + Playwright) drives the
  lane's demo host, which serves the components from source on an ephemeral port, and a stub
  `ITransitionClient` is compiled into the story that hosts the document. No dependency on AppBox,
  which is backend/harness-owned.
- **Deviation from the first plan, recorded**: the first draft said "publish a consumer page
  through `ConsumerAppHost`". That path restores the *published packages* from an offline feed, so
  it would have required a package batch, and publication is a separate authorization. The demo
  host proves the same behavior without one: real browser, real components, ephemeral port,
  scripted transport. A packaged-consumer proof stays available as a separate scope if a consumer
  regression ever needs it.
- **The stub is the contract under test**: applied, refused, conflict and invalid are scripted in
  the page's client, so the browser proves the component's behavior, not a live graph.
- **Chromium is the documented dedicated browser** Playwright manages; no user browser is
  attached to.
- **Direct assertions on the DOM**, using the `data-slot`/`data-result-*` attributes the
  components already emit; no screenshot comparison.

## Acceptance criteria

- [x] UAC01: Given a document in the hosted page, when the browser opens it, then the declared labels and values render and no property key is visible as text.
- [x] UAC02: Given declared relations and actions, when the page renders, then relations are read-only text and the actions are offered.
- [x] UAC03: Given the applied stub, when the action is activated, then the region updates to the returned document and the result cases are shown.
- [x] UAC04: Given the refused stub, when the action is activated, then the refusal case renders and the document shown is unchanged.
- [x] UAC05: Given the conflict stub, when the action is activated, then the response's document is shown and the retry action is offered.
- [x] UAC06: Given a keyboard user, when a result arrives, then focus is on the result region and an assistive-technology-visible announcement carries the outcome.
- [x] UAC07: Given the whole page, when it is inspected, then no page-specific document markup exists outside the components' slots (the page composes the two components only).

## Boundaries

- Browser proof of the components only; the deployed Graph record page is graph's own acceptance
  (`KRNL0031`/`KRNL0056` family), not this scope.
- No live network call is made from the page; the transport stays stubbed.
- No visual regression baseline beyond direct DOM assertions.

Observed in the browser: the document renders its declared labels and values with no property key in
the visible text; relations are read-only text and the declared action is offered; running the action
shows the applied case with `data-severity="success"` and reports `applied` to the host; a refusal
shows its message and its field error; a conflict shows the moved record's message and its `retry`
action; the result region is `role="status"` with `aria-live="polite"`, takes focus after a keyboard
run, and the host page adds no document markup of its own.

The story lives in `Examples/Documents` rather than `Examples/Data` because `.gitignore` carries
`src/**/data/`, which silently ignores new files in that folder on a case-insensitive checkout; the
story is still grouped under `Data` by its display name.
