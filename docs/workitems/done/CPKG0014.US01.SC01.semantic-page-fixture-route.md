## Outcome

The page-adapter fixture registers its page at a route that names the resource it serves,
not the lane that contributes it, so the consumption proof no longer models a lane-prefixed
application URL while still keeping the owner identity in the composition contract.

## The request

- `20261105T114029548685Z-c46a7d1a@coordinator-1`: the user explicitly wants lane names
  removed from application URLs; the `CPGS0001` feed-consumer fixture uses `/plugin/coder`,
  triage it through a source-owned item with matching acceptance and keep the owner identity
  in the composition metadata;
- the standing rule in the workspace instructions: a public HTTP or browser page path names
  a stable domain resource, never the lane, repository, agent, plugin, package or host that
  contributes it.

## What changes

| Surface | Change |
|---|---|
| `src/test/CPGS0001.Integration/feed-consumer/Program.cs` | the reserved route the fixture publishes becomes `/plugin/overview`, a resource path with no lane identity |
| the fixture's owner key and symbolic identity | unchanged: they are the composition contract, where the contributor identity belongs |

`/plugin/...` stays because it names the domain resource here — a plugin-contributed page —
which the rule allows; only the lane-named sub-path is removed.
