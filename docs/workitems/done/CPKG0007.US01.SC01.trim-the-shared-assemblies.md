## Outcome

A consumer that publishes trimmed trims the shared assemblies instead of copying
them byte for byte, and the two public `Type` members that carry a type across the
package boundary declare which members a consumer has to keep. The shared surface
therefore stops being a fixed 2,695,168 bytes of every trimmed browser client and
stops being the place where a consumer discovers a missing annotation.

## The request

- `20261101T110901272433Z-af35e5c1@builder`: the linker copies an assembly that
  does not declare `<IsTrimmable>true</IsTrimmable>` unchanged; measured with
  `dotnet publish src/wasm/LowlandTech.Builder.Wasm -c Release -p:PublishTrimmed=true`,
  the Builder frontend shrinks from 4,340,224 to 967,680 bytes, while
  `LowlandTech.Components` stays at 1,210,880, `LowlandTech.Components.Blocks` at
  1,422,848 and `LowlandTech.Components.Core` at 61,440 bytes;
- `20261101T105232425773Z-387d1e1a@builder`: the frontend cannot name the members of
  a type the package hands over — `ComponentDescriptor.ComponentType` does not say it
  keeps its public constructor, and `PropertyGridAttribute.OptionsProvider` does not
  say it keeps its properties and fields.

## What changes

| Surface | Change |
|---|---|
| the packable projects | declare `<IsTrimmable>true</IsTrimmable>`, which marks the assembly trimmable and keeps the trim analyzer armed |
| `ComponentDescriptor.ComponentType` | `[DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicParameterlessConstructor)]` |
| `PropertyGridAttribute.OptionsProvider` | `[DynamicallyAccessedMembers(PublicProperties \| PublicFields)]` |

## Acceptance

- [x] UAC01: Given the two published packages, when the trim analyzer builds each of them, then both still report zero warnings with the trimmable declaration in place.
- [x] UAC02: Given a consumer that publishes trimmed against the batch, when the publish runs, then the three shared assemblies are smaller than the assemblies the packages ship, so the linker trimmed them instead of copying them.
- [x] UAC03: Given the annotated contract, when the annotations are read from the published assembly, then `ComponentDescriptor.ComponentType` declares the public parameterless constructor and `PropertyGridAttribute.OptionsProvider` declares public properties and public fields.
- [x] UAC04: Given the new batch, when a consumer pins it with the current Core, then a package-only restore reports no `NU1107` and no `NU1608`, and the version and digests are published to the consumers.

## Boundaries

- The annotations declare what a consumer must preserve; they do not change the
  runtime shape of the contract or the persisted payloads.
- The package is published to the workspace feed only; public feed publication and
  deployment stay outside this scope.
- No consumer repository is edited here; the Builder repoints its own copies.

### Measured constraint that the consumers have to know

A consumer that explicitly sets `TrimMode=partial` cannot load the batch: the SDK
drops the trimmed package assembly from `deps.json`, so the host reports
`Could not load file or assembly 'LowlandTech.Components.Blocks'` even though the
trimmed file is in the output directory. The same consumer with
`TrimMode=partial` and the previous, non-trimmable batch runs, and the same consumer
with the `.NET 10` default (`TrimMode` unset, which is `full`) runs against this
batch. The Builders's `LowlandTech.Builder.Wasm` sets no `TrimMode`, and the SDK
defaults `partial` only below `.NET 8`, so the requesting consumer uses the working
configuration. The constraint is recorded here and in the consumer notification
instead of being left for a consumer to discover.

`LowlandTech.Components.Core` stays at its published generation because the Core
producer pins that generation exactly; making the contracts assembly trimmable needs
a contracts generation the Core pins, which is a Core-owned decision and not this
scope.
