## Outcome

A host that runs a document action can render what happened without inventing markup: one
result carries the outcome, every result case (success, refusal, problem, conflict) with a
stable code, a severity, text keys and field errors, the actions it offers, and the resulting
document as an opaque payload. Components renders the cases; the graph runtime produces them.

## The request

Graph's data-defined transitions return inspectable results (`KRNL0048`). The user approved the
envelope:

- every result case is **structured data keyed by a stable code** — no HTML or CSS is stored in
  transition data, and no fragment language becomes a second UI;
- validation returns outcome plus cases plus observed evidence and **no document**, because
  validation is a sandbox;
- execution returns outcome plus cases plus the **authoritative document and its causal head**,
  including on refusal and conflict, so one round trip tells the client the truth;
- wording is keys resolved by the client (Graph may ship generic defaults), never prose baked
  into the runtime.

Components owns the contract and the rendering; it must not depend on Graph's payload types and
must not model the document itself.

## What changes

| Surface | Change |
|---|---|
| `TransitionResult`, `ResultCase`, `ResultAction`, `TransitionOutcome`, `ResultSeverity` (`src/core/Transitions`) | the envelope: outcome, cases keyed by code, severity, text keys and arguments, field map, observed evidence, offered actions, opaque document and head |
| `TransitionResultView` (`src/lib/TransitionResult`) | renders the outcome, one block per case, field errors, and the offered actions; text comes from a host-supplied resolver and the observed evidence is opt-in |
| existing components | untouched: `Alert`, `Field`, `Button` and the forms keep their contracts |

The document stays opaque (`string` holding the payload the host got). Rendering the document is
`CPKG0019`/`CPKG0020` plus a later document view, not this scope.

## Acceptance criteria

- [x] UAC01: Given a result with an outcome and cases, when the view renders, then the root reports the outcome and each case renders with its severity.
- [x] UAC02: Given a case with a title key, a message key and arguments, when it renders, then the host resolver supplies the text and the key is never shown raw.
- [x] UAC03: Given a refusal with field entries, when it renders, then each field shows its resolved message against that field name.
- [x] UAC04: Given offered actions, when a person activates one, then the host callback receives that action; a disabled action raises nothing.
- [x] UAC05: Given observed evidence, when the view renders with evidence hidden, then nothing from it appears; when shown, then each entry appears under its own name.
- [x] UAC06: Given a result that carries a document and head, when the view renders, then it neither parses nor renders them, and the payload is available to the host unchanged.

## Boundaries

- Presentation contract only: severity, keys, arguments, field map, observed evidence and offered actions. No layout language, no HTML or CSS in data, no per-case markup authored by a consumer.
- The library stays domain-agnostic: no CORBIS, Graph or transition-runner types; the document is opaque and the outcome vocabulary is closed.
- Text resolution belongs to the host (`Func<string, string>`), so localization stays in the app's resources rather than the library.
- Observed evidence is diagnostics, off by default, because it names model concepts a person must not see.

The view was measured with a host resolver: the title and message keys resolve ("Saved",
"The record Ada was saved.") and neither key appears in the markup; a field refusal renders its
message against `data-result-field="country"`; the offered action raises its key while the
disabled action raises nothing; observed evidence stays hidden until `ShowObserved`; the document
payload and head travel untouched and are never parsed or rendered.

The complement on the runtime side is a graph handoff: `KRNL0051` returns outcome, cases and
observed evidence with no document (validation is a sandbox), and the existing execution path (`KRNL0031`) returns the envelope with the authoritative document and head, and `KRNL0056` renders it. No HTML or CSS fragment is stored in
transition data; a render projection can be added later if a non-Blazor consumer needs one.
