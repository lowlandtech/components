## Outcome

A host that renders a document whose properties are declared at runtime — a key/value set with
type metadata from the document definition, not a compiled model — can use `DataForm` instead of
hand-written field markup, because the form accepts the fields and the values it is given.

## The request

Graph's `KRNL0031` renders CORBIS documents whose properties are declared at runtime. `DataForm`
discovers fields by reflecting a typed model, so over a dictionary it finds nothing and the
renderer falls back to per-field markup. Graph asked Components for a supported dynamic path:
an explicit `IReadOnlyList<DataFormField>` plus a dictionary of values. No new field types are
needed.

## What changes

| Surface | Change |
|---|---|
| `DataForm.Fields` | an optional explicit field list; when supplied it is used verbatim (ordered by `Order`) and the model is not reflected |
| `DataForm.Values` | an optional value dictionary keyed by field name; display, edit, reset and change callbacks read and write it instead of the model's properties |
| model path | unchanged: with no `Fields`, fields still come from the model's public properties and values from the model |

The value dictionary is the document's own storage, so the host keeps ownership of the document
and the form only edits the entries it was given.

## Acceptance criteria

- [x] UAC01: Given a document whose fields are declared at runtime, when the host passes those fields to the form, then the form renders one labelled control per declared field and reflects no model.
- [x] UAC02: Given the same form with a value dictionary, when it renders, then every control shows the value stored under its field name.
- [x] UAC03: Given that form, when a person edits a value, then the dictionary entry carries the new value and the change callbacks report the field name and value.
- [x] UAC04: Given a declared field marked read-only, when the form renders it, then the value is shown without an editable control.
- [x] UAC05: Given a model-based form, when it renders, then its fields and values still come from the model and no behaviour changes.

## Boundaries

- Additive surface only: no existing parameter changes meaning, and a form without `Fields`
  behaves exactly as before.
- Validation stays with the host: the dynamic path has no `EditContext` over a typed model, so
  the form renders the host's validators and messages but does not invent attribute validation
  for runtime-declared properties.
- No new field types and no second renderer: the dynamic path reuses `FormField`.
