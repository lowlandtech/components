# CPKG0012-US01-SC01 — Keep the injected members of a block alive under trimming

- **Work:** M14-001

## Outcome

A trimmed host can render a block page. The injected and cascaded members that
`BlockBase` declares survive trimming, so the renderer assigns `BlockContext`, the
session settings and the parent mode instead of failing on a member the trimmer removed,
and the batch that carries the declaration is published with its digests.

## The defect

The residual-trim probe of `CPKG0006` published a consumer that renders a block page and
ran it:

```
System.InvalidOperationException: Cannot provide a value for property 'BlockContext'
on type 'Cpkg0006.Consumer.HookHost' because the property has no setter.
```

`BlockBase` declares `[Inject] protected BlockContext? BlockContext { get; set; }` and two
protected `[CascadingParameter]` members. The renderer assigns them by reflection, and
because the assemblies became trimmable in `CPKG0007`, the linker removed setters that
nothing named — a regression this lane introduced with the trimmable declaration and
caught only by a trimmed render.

## What changed

`BlockBase` gains a protected constructor that carries
`[DynamicDependency(NonPublicProperties | PublicProperties, typeof(BlockBase))]`, so the
class roots its own members whenever a block type is kept. A class-level dependency is not
allowed by the attribute, and an empty static constructor is removed with its attribute;
the instance constructor that every block runs is the member that survives.

## Follow-up that this scope does not close

The same probe shows that `SessionOutboxList.SerializePayload` falls back to
`payload.ToString()` in a trimmed host: the suppressed `IL2026` hides a reflection-based
serialization that fails at run time for a payload type the package cannot name. That is
tracked as the open acceptance of `CPKG0006` (UAC03) and needs an additive way for a host
to hand over the payload contract.
