## Outcome

Plugin session block lookup resolves only validated active owned descriptors.

## Refinement

Triaged 2026-10-24 by the components lane under the released refinement phase
`components-CBLK0001-US01-SC01-refinement`. This pass refined the scope only:
it implemented no production behavior and no acceptance criterion executed.
The scope stays `backlog` until the coordinator releases the execution phase.

**Chosen surface.** The session block surface that Components already owns in
`src/blocks/Session`: `ISessionBlockDescriptor`, `ISessionBlockRegistry`,
`ISessionBlockDiscovery`, `SessionBlockDescriptor`, `DefaultSessionBlockRegistry`,
`AssemblyScanningSessionBlockRegistry` and `SessionBlockDiscovery`. The bridge
projects the plugin owners that are active onto those existing contracts, so a
host keeps resolving blocks the way it does today and only the *owner* decides
whether a block is published.

**The gap the review named.** A loaded type is not proof of active ownership.
`AssemblyScanningSessionBlockRegistry` publishes every loaded `ComponentBase`
under its own type name, so a plugin component stays reachable after its owner
withdrew. The bridge closes that path: an owned type is reachable only through
the validated node type key of an active owner.

**Host authority.** The host owns which plugin owners are active and delivers
that authority to the bridge as a revision. The bridge projects the owners of
the revision it holds, and a withdrawal is delivered as the next revision. The
block bridge holds no retained fragment, so it needs no subscriber contract:
every lookup reads the revision the bridge holds.

**Planned Components-owned contracts** (namespace `LowlandTech.Components`, in
`src/blocks/Session`):

- `SessionBlockCandidate(string OwnerKey, string NodeTypeKey, string SymbolicIdentity, int Priority, string Label, string Icon)`
- `SessionBlockOwnerSnapshot(long Revision, IReadOnlyCollection<string> ActiveOwnerKeys)`
- `SessionBlockOwnerBridge` with
  `SessionBlockOwnerBridge(ComponentsStartupMap, SessionBlockOwnerSnapshot, IEnumerable<ISessionBlockRegistry>)`,
  `Publish(SessionBlockCandidate)`, `Deliver(SessionBlockOwnerSnapshot)`,
  `Revision`, `Snapshot`, `IsOwnerActive(string)` and the `ISessionBlockRegistry`
  member `GetDescriptors()`
- `SessionBlockCandidateValidation(SessionBlockCandidate Candidate, bool IsValid, IReadOnlyList<SessionBlockCandidateError> Errors)`
- `SessionBlockCandidateError(SessionBlockCandidateErrorCode Code, string Subject, string Message)`
- `SessionBlockCandidateErrorCode` with the members `DuplicateNodeTypeKey`,
  `ConflictingNodeTypeKey`, `UnresolvedComponent` and `WrongComponentType`

**Trusted component mapping.** A candidate carries a symbolic identity, never a
type. The identity resolves through the trusted startup map of `M2-001`
(`ComponentsStartupMap`), so a plugin cannot contribute an arbitrary type: only
the startup binding the host itself registered decides which type an identity
becomes. A candidate whose identity does not resolve, or resolves to a type
that is not a renderable component, is refused by name.

**Validate one candidate before publication.** A candidate is validated before
it is published, and a refused candidate changes nothing — the previously
published lookup stays exactly as it was:

- the same owner already claimed that node type key — `DuplicateNodeTypeKey`
- another owner already claimed that node type key — `ConflictingNodeTypeKey`
- the symbolic identity does not resolve — `UnresolvedComponent`
- the resolved type is not a renderable component — `WrongComponentType`

The node type key stays reserved by the owner that claimed it, whether that
owner is active or not, so a second owner cannot take the key over while the
first one may return.

**Host defaults stay available.** The bridge wraps the host registries and
publishes the host descriptors beside its own. A host default keeps its own
node type key; when an owned descriptor overrides a host default by priority,
the host descriptor stays in the registry and becomes the fallback again once
the owner withdraws.

**Every lookup path is filtered.** The bridge suppresses the assembly-scanning
shape of an owned type — the descriptor that carries the owned type under the
type's own simple name — from every host registry it wraps. A host default
that shares the component type with an owned descriptor keeps its own node type
key, so the host fallback survives. After the withdrawal the owned type is
unreachable through every path: not under its node type key, and not under its
type name.

**Wiring.** The bridged host registers the bridge as its single
`ISessionBlockRegistry` and hands it the host registries. The base DI-only
mode keeps registering `DefaultSessionBlockRegistry` and
`AssemblyScanningSessionBlockRegistry` directly and stays unchanged.

**Independent of the panel scope.** The block bridge carries its own owner
snapshot contract, so this scope stays deliverable on its own. The two
snapshots have the same shape; a host that already owns the panel authority of
`CPAN0001` maps one onto the other.

**Acceptance inventory.** `src/test/CBLK0001.Integration/US01.ActiveOwnedBlocks/`:
one expression-bodied Shouldly Fact per UAC in `SC01_ActiveOwnedBlocks.cs`, the
contract accessor `ComponentsBlockOwnerContracts.cs` and the plugin component
`FakePluginSessionBlock.cs`. The accessor reaches the planned contracts by
their documented names and fails with the exact missing contract name, so an
unimplemented contract can never turn into a silent pass. The plugin component
is a public component in the test assembly on purpose: the assembly-scanning
fallback publishes every loaded component under its own type name, so it is
exactly the reappearance path the withdrawal has to close. The Facts arrange
the owned candidates, the active and inactive owners, the host defaults and
the scanning fallback, and they query the real `SessionBlockDiscovery`.

Every Fact is skipped and names its missing dependency:

- UAC01 — the block owner bridge does not exist yet, so no owned candidate can
  be validated before publication.
- UAC02 — the block owner bridge does not exist yet, so no owned descriptor can
  take part in the resolution of the active owners.
- UAC03 — the block owner bridge does not filter the assembly-scanning fallback
  yet, so a withdrawn plugin component can still reappear as a plugin
  contribution.

**No browser scenario in this scope's inventory.** The browser proof of this
scope is the separate Interactive Server RCL consumer with host defaults and
active-owner filtering that the consumer integration boundary names; that

**Dependencies.** `CPLG0001-US01-SC01` (M2-001) is at `review` and carries the

## Implementation

Executed 2026-10-25 by the components lane under the released implementation
phase `components-CBLK0001-US01-SC01-implementation`. This pass implemented the
planned contracts and proved them with the executed unit scenario and the
executed browser scenario. The scope moves to `review`; only the coordinator
accepts it.

**The contracts.** `src/blocks/Session/SessionBlockOwnerContracts.cs` carries the
candidate, the owner snapshot, the named refusal and the refusal codes.
`src/blocks/Session/SessionBlockOwnerBridge.cs` carries the bridge. The public
contracts of `src/core` and `src/lib` are unchanged: the bridge uses the
trusted startup map `ComponentsStartupMap` of `M2-001` and the existing
`ISessionBlockRegistry`, `ISessionBlockDescriptor` and `ISessionBlockDiscovery`
contracts of the Blocks package as they are.

**A candidate is validated before it is published.** A refused candidate changes
nothing: the published lookup stays exactly as it was. The node type key stays
reserved by the owner that claimed it, whether that owner is active or not, so
a second owner cannot take the key over while the first one may return.

**Host defaults stay available.** The bridge wraps the registries of the host
and publishes their descriptors beside its own. A host default keeps its own
node type key; when an owned descriptor overrides a host default by priority,
the host descriptor stays in the registry and becomes the fallback again once
the owner withdraws.

**Every lookup path is filtered.** The bridge suppresses the assembly-scanning
shape of an owned type — the descriptor that carries the owned type under the
type's own simple name — from every host registry it wraps. A host default that
shares the component type with an owned descriptor keeps its own node type key,
so the host fallback survives. After the withdrawal the owned type is
unreachable through every path: not under its node type key, and not under its
type name.

**The wiring.** The bridged host registers the bridge as its single
`ISessionBlockRegistry` and hands it the host registries. The base DI-only mode
keeps registering `DefaultSessionBlockRegistry` and
`AssemblyScanningSessionBlockRegistry` directly and stays unchanged.
`SessionBlockDiscovery` reads the registries it is built over once, so a host
that caches its discovery rebuilds it for every resolution round; the consumer
of this scope does exactly that, and the revision the bridge holds is the one
that decides.

**The consumer proof.** `src/test/CBLK0001.Integration/consumer/` is a separate
Interactive Server RCL consumer that restores the three Components packages
from an offline feed, registers the host default registry and the
assembly-scanning fallback, publishes the block of an active plugin owner
through the bridge and resolves the blocks of its circuit. It owns a
consumer-owned `ConsumerBlockAuthority` that delivers the revisions of the host
to every live circuit. There is no reverse reference to Coder or to the
Components demo host, and the consumer sources are excluded from the test
assembly through `DefaultItemExcludes`, never through the `Compile Remove`
list.

**The browser proof.** `src/e2e/CBLK0001.Integration/US01.ActiveOwnedBlocks/`
publishes that consumer, serves it, opens it in two browser contexts and
withdraws the owner while both circuits are live. It asserts the real cleanup:
both circuits lose the owned block and fall back to the host default, the
assembly-scanning shape of the owned type stays closed in both circuits, and
the deployed stylesheet of the package stays served with 200 and stays linked
in both circuits.
