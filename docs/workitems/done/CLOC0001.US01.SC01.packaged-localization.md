## Outcome

A consumer of the Components packages reads the localized labels of the
packages. The labels resolve for a host that registers the localization without
a resources path and for a host that registers it with one.

## The defect

The Harness lane reported on 2026-10-27 that the packaged localization of
`LowlandTech.Components` never resolves and that `IStringLocalizer<T>` always
answers with the key. Its message `20261027T010117550273Z-e53f5c8a@harness`
names the observed cause: `ResourceManagerStringLocalizerFactory` asks for the
full name of the type, so a resource of `CommandPaletteStrings` has to carry the
manifest name `LowlandTech.Components.CommandPaletteStrings.resources`, while
`src/lib/LowlandTech.Components.csproj` produced
`LowlandTech.Components.Resources.CommandPaletteStrings.en.resources`, which
carries an extra `Resources` segment and the culture. The evidence of the
report is the Harness work item
`docs/workitems/doing/HARN0004.US03.SC01.package-only-coder-style-consumer-acceptance.md`.

The packaged consumer of this repository already answered with the key: the
consumer application of the CPKG0001 packaging acceptance registers the
localization without a resources path, so it asked for the full name of the
type and found nothing.

## What the naming contract asks for

The lane measured the contract of the framework instead of guessing it, with a
probe over the built assemblies of this repository and over the shell of the
Harness lane:

| Host registration | Base name the factory asks for | Result before this scope |
|---|---|---|
| `AddLocalization()` | `LowlandTech.Components.DataFormStrings` | the key |
| `AddLocalization(o => o.ResourcesPath = "Resources")` | `LowlandTech.Components.Resources.DataFormStrings` | the label |

Two rules follow from the measurement:

1. The name of a resource carries the namespace of its type and not the path of
   its file, so the manifest name of `DataFormStrings` is
   `LowlandTech.Components.DataFormStrings.resources` and not
   `LowlandTech.Components.Resources.DataFormStrings.resources`. A host that
   configures a resources path asks for the second name, because the path is
   inserted between the assembly and the type.
2. The English resource of a type is the neutral resource of that type and
   travels in the assembly of the package itself. A resource of a culture
   travels in the satellite of that culture under the name that carries the
   culture.

The hosts of this workspace configure `Resources`, and the hosts that consume
the published packages — the Harness shell and the packaged consumer of the
CPKG0001 acceptance — register the localization without a resources path. The
packages therefore carry both names, so neither host style loses a label.

## The change

`src/lib/LowlandTech.Components.csproj` and
`src/blocks/LowlandTech.Components.Blocks.csproj`:

- The default glob of the embedded resources is replaced by an explicit list,
  because a file can carry only one manifest name per path and the packages
  need two.
- Every resource is embedded under the name of its type, and the English
  resource of every type is the neutral resource: `CommandPaletteStrings.en.resx`
  became `CommandPaletteStrings.resx`, and the same for `DataFormStrings`,
  `DataGridStrings`, `WorkStateBadgeStrings` and `SessionBlockStrings`.
- A second copy of every resource carries the name a host with a resources
  path asks for.

The public contracts of the packages are unchanged: no type moved, no
dependency changed and the resource keys of the `.resx` files are untouched.

## Acceptance

The Facts of `src/test/CLOC0001.Packaging/US01.Localization/SC01_PackagedLocalization.cs`:

- [x] UAC01: Given a host that registers the localization without a resources path, when it reads the label of a type of the controls package, then it reads the English label of the package instead of the key.
- [x] UAC02: Given a host that registers the localization without a resources path, when it reads the label of a type of the controls package in Danish, then it reads the Danish label out of the satellite of that culture.
- [x] UAC03: Given a host that configures the resources path of this workspace, when it reads the labels of a type of the controls package in English and in Danish, then it reads both labels instead of the key.
- [x] UAC04: Given a host that registers the localization without a resources path, when it reads the labels of a type of the blocks package in English and in Danish, then it reads both labels instead of the key.
- [x] UAC05: Given the controls package and the blocks package, when the manifest names of their assemblies are read, then every type of them carries a neutral resource in the assembly of its package.
- [x] UAC06: Given the controls package, when the manifest names of its Danish satellite are read, then the satellite carries the resource of every type under the name that carries the culture.
- [x] UAC07: Given the controls package as it is packed into a feed, when the payload of the package is read, then it carries the neutral resource of every type and the satellite of every culture, and a host without a resources path reads the English label out of the package itself.

The drift guards of the existing localization scopes stay valid: the English
resource of a type is now the neutral file of that type, so the catalog parity
of `SPEC1072` and `SPEC1062` reads the neutral file.

## A finding for the Harness lane

The measured contract shows that a satellite carries the resource of its
culture under the name that carries the culture. The shell of the Harness lane
strips the culture from that name, so the satellites of the shell do not answer
for their culture: a Danish lookup of `LowlandTech.Shell.HeaderStrings` in the
built shell of the Harness lane returns the English `Tenants` instead of the
Danish `Lejere`. The finding is reported to the Harness lane in hub chat.
