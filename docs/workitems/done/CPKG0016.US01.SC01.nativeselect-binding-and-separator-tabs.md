## Outcome

`NativeSelect` takes part in the two-way value binding the rest of the form controls
already use, and `TabsList` offers the separator variant the application's language switch
draws, with the stylesheet it needs shipped in the package. Both are published in one batch
from a committed, verified checkpoint.

## The request

The user edited the checkout directly and asked for a new Components package; coordinator-1
recorded the state and asked this lane to own it rather than publish the dirty checkpoint:

- `src/lib/NativeSelect/NativeSelect.razor` and `.shared.cs` — a `Value`/`ValueChanged` pair,
  the `value` attribute and an `@onchange` handler;
- `src/lib/Tabs/TabsList.razor` — a `separator` variant (also accepting the misspelling
  `seperator` the application uses), with a new `src/lib/wwwroot/css/tabs.css`.

No Components workitem covered any of it, so this scope owns it, tests it and publishes it.

## What changes

| Surface | Change |
|---|---|
| `NativeSelect` | `Value` and `ValueChanged` parameters, the rendered `value`, and one change handler that writes the value and raises the callback |
| `TabsList` | the `separator` variant emits `cn-tabs-list-seperator`; the misspelled `seperator` is accepted because the application uses it |
| `wwwroot/css/tabs.css` | the stylesheet for that variant ships as a static asset, with the link a consumer needs recorded in the file |

## Acceptance

- [x] UAC01: Given a NativeSelect whose caller sets `Value`, when it renders, then the rendered `select` carries that value.
- [x] UAC02: Given a NativeSelect whose caller listens for changes, when the selection changes, then the callback receives the new value.
- [x] UAC03: Given the same change, when the component re-renders, then `Value` holds the new selection, so the control shows what the user chose.
- [x] UAC04: Given a caller that uses `@bind-Value`, when the selection changes, then the bound field holds the new value.
- [x] UAC05: Given a TabsList with `Variant="separator"`, when it renders, then the list carries `cn-tabs-list-seperator`.
- [x] UAC06: Given a TabsList with the application's `Variant="seperator"` spelling, when it renders, then the list carries the same class.
- [x] UAC07: Given a TabsList with another variant, when it renders, then it does not carry the separator class.
- [x] UAC08: Given the published package, when its contents and the stylesheet's guidance are inspected, then `css/tabs.css` is present and names the link tag a consumer adds.

### The suite failure that this scope does not own

`src/test/CPKG0001.Packaging/consumer-scenario.ps1` resolves the ASP.NET framework version with
`Get-AspNetCoreRuntimeVersion` (line 499) and copies that exact framework package from
`~/.nuget/packages` (line 462) into its private feed. On this machine the resolver now returns
`11.0.0`, the cache holds no `microsoft.aspnetcore.app.internal.assets` at all, and the installed
runtimes are `8.0.34`, `9.0.23` and `10.0.15` — so the scenario cannot assemble its feed and both
packaging scopes fail before they exercise anything.

That script belongs to the completed `CPKG0001`, so this scope does not edit it. The finding and
the recovery are reported to coordinator-1 (`20261116T001942696958Z-84907f2a@components`) so the owning item can be returned to `doing`: the resolver should prefer an
installed runtime's shared version over a metadata-derived one, or the copy step should accept the
highest cached generation.
