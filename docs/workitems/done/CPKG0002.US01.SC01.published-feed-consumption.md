## The state of the harness

`src/test/CPKG0001.Packaging/consumer-scenario.ps1` packs
`LowlandTech.Components.Core`, `LowlandTech.Components` and
`LowlandTech.Components.Blocks` from this repository into a private feed,
copies the selected upstream Core package and the closure the consumer needs
into the same feed, writes a temporary consumer and restores that consumer
against the private feed alone with an isolated global-packages folder.

The harness already knows how to copy packages of the local feed into the
scenario feed: the parameter `FeedPackages` copies every version of a package id
of the local feed into the scenario feed, and the parameter `AdditionalPackages`
packs additional projects of this repository into the same feed. What it cannot
do is to consume the published batch of the shared feed *as the packages under
test*, because the pack of this repository always wins for the three base
packages.

## The switch this scope refines

The harness gains a switch that selects the published identities of the shared
feed for the packages under test. With the switch selected, the harness copies
the published packages of the shared feed into the scenario feed instead of
packing the packages of this repository, and the dependency closure of the
copied packages travels with them, so the consumer never reaches outside the
scenario feed. Without the switch, the harness keeps packing the packages of
this repository, so the gate of the closed CPKG0001 scope is unchanged.

## The change this scope delivers

The harness of `src/test/CPKG0001.Packaging/consumer-scenario.ps1` gained the
switch `UsePublishedBatch`. With the switch selected, the three base packages
are copied from the shared feed under the version that the selected Core
package pins, instead of being packed from the sources of this repository, and
the dependency closure of the copied packages travels with them, so the
consumer still resolves everything from the scenario feed alone. The additional
packages of this repository are not part of the published batch and are still
packed. Without the switch the harness keeps packing the packages of this
repository, so the gate of the closed CPKG0001 scope is unchanged.

The manifest of the scenario names the source of the packages under test, so an
acceptance can tell a consumed published batch from a fresh pack.

## Acceptance

The Facts of `src/test/CPKG0002.Packaging/US01.Feed/SC01_PublishedFeedConsumption.cs`:

- [x] UAC01: Given the packaging harness of this repository, when its parameters are read, then it offers a switch that copies the published identities of the shared feed into the scenario feed instead of packing them.
- [x] UAC02: Given a scenario that selects the published batch of the shared feed, when the scenario runs and the consumer restores, then the consumer resolves the published versions of the packages and not a fresh pack.
- [x] UAC03: Given a scenario that does not select the published batch, when the scenario runs, then the packages of this repository are packed into the scenario feed and the gate of the closed CPKG0001 scope is unchanged.
- [x] UAC04: Given a scenario that selects the published batch of the shared feed, when the scenario feed is assembled, then the dependency closure of the copied packages travels with them and the consumer never reaches outside the scenario feed.
