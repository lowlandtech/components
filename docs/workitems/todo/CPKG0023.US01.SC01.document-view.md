## Outcome

A host hands one component a document — its type, declared properties with labels and value
kinds, values, relations, causal head and the actions it offers — and gets a record view: labels
instead of keys, read-only values, read-only relations and the offered actions. No per-page
markup, no emitted model for the form to reflect.

## Refinement decisions (2026-11-26)

- **Labels come from the definition.** `DocumentDefinition.Properties[].Label` is authoritative;
  a host may override with a label map. When neither resolves, the view renders the value without
  a label and never falls back to the property key.
- **Value kinds are a closed set** — `text`, `number`, `decimal`, `bool`, `date`, `datetime`,
  `guid`, `json`, `selection` — mapped to `FormFieldType` by the view, the same mapping the app
  hand-writes today.
- **The document is opaque to the parser**: the host builds the `DocumentSnapshot`; the view only
  renders it. Components still never models storage.
- **No design-surface descriptor** in v1: the view is host-composed, and `[Properties]` would
  expose a data contract as editable design properties. Revisit only if the palette needs it.

## What changes

| Surface | Change |
|---|---|
| `DocumentSnapshot`, `DocumentDefinition`, `DocumentPropertyDefinition`, `DocumentRelation`, `DocumentAction`, `DocumentInput` (`src/core/Documents`) | the rendering contract, trim-safe records, mirroring the payload shape the runtime already returns |
| `DocumentView` (`src/lib/DocumentView`) | read-only properties through `DataForm.Fields`/`Values`, relations through `DynamicEdgeForm.ReadOnly`, declared actions as buttons with their inputs, a head badge and a result slot |

## Acceptance criteria

- [ ] UAC01: Given a definition whose properties carry labels, when the view renders, then every property shows its label and value and no property key appears as visible text.
- [ ] UAC02: Given declared relations, when the view renders, then each shows its label, counterpart and direction as text with no input element.
- [ ] UAC03: Given a property marked required or read-only, when it renders, then required is visibly marked and the read-only value offers no edit.
- [ ] UAC04: Given declared actions, when the view renders, then each action shows its label and exactly the inputs its contract declares.
- [ ] UAC05: Given a label that resolves through the host map, when the view renders, then the mapped text is shown; given one that resolves nowhere, then the value renders without a label and the key is not shown.
- [ ] UAC06: Given a document with no actions, when the view renders, then nothing invites an edit and no form submits.

## Boundaries

- Read-only presentation: this scope does not write the document. Editing and actions are `CPKG0024`.
- No transport, no Graph types, no HTML or CSS from data; the head is displayed as an identifier,
  not interpreted.
- The relation view reuses `DynamicEdgeForm.ReadOnly`; it does not grow a second relation control.
