repository can publish that client trimmed. The shared components carry no trim

## The three families of the warnings and their owners

### The reflection-based JSON — IL2026, 47 warnings

`System.Text.Json.JsonSerializer.Serialize` and `Deserialize` carry
`RequiresUnreferencedCodeAttribute` in the overloads that take a
`JsonSerializerOptions`, and `Assembly.GetTypes()` carries it as well. The callers
in this repository are:

- the persisted state of the components that keep a JSON shape across a reload:
  `TreeView/TreeView.razor.cs` (6), `Resizable/Resizable.razor` (2),
  `ContainerGrid/ContainerGrid.razor.cs` (3), `Feed/SessionContext.cs` (1),
  `Feed/BlockContext.cs` (1), `Showcode/StoryCard.razor` (4),
  `Showcode/ShowcodeNav.razor` (2), `Showcode/StoryRegistry.cs` (1);
- the session and work models of `src/blocks`: `Session/SessionModels.cs` (3),
  `Session/SessionContextTreeNode.razor.cs` (3), `Session/SessionStateService.cs` (2),
  `Session/AgentSelectionService.cs` (2), `Session/SessionEventLogEntry.razor.cs` (1),
  `Session/SessionOutboxList.razor.cs` (1), `Session/SessionContextExplorer.razor.cs` (1),
  `Session/SessionBlockDiscovery.cs` (1), `Work/WorkModels.cs` (3);
- the dynamic entity runtime of `src/blocks`:
  `Session/HttpDynamicNodeRuntime.cs` (7), where `ToInstance` serializes a
  dictionary and deserializes it into a `Type` that is only known at run time;
- the designable component discovery: `Designable/ComponentDescriptorRegistry.cs` (1),
  where `Discover` reads `asm.GetTypes()` of every loaded assembly.

The fix shape the Builder lane named is the one the runtime offers: a
source-generated `JsonSerializerContext` that names the shape of every persisted
state, so no shape is resolved by reflection at run time. The dynamic entity
runtime and the assembly discovery cannot be named by a context, because their
shape is not known when the context is generated; they need a trim-safe contract
of their own.

### The missing member annotations — IL2075, IL2070, IL2072, IL2067, 38 warnings

A `Type` or an `object` that reaches `Type.GetProperty`, `Type.GetProperties`,
`Type.GetMethods`, `Type.GetField` or `Activator.CreateInstance` has to declare
which of its members the code uses, or the trimmer cannot keep them.

- `DataForm/DataForm.razor.cs` (6 IL2075, 1 IL2072) reads and writes the model
  of the form through `Model.GetType().GetProperty(propertyName)` and creates the
  default value of a value type through `Activator.CreateInstance(underlying)`;
  the model is an `object`, so the members that survive the trim are not known;
- `Designable/ComponentDescriptorRegistry.cs` (3 IL2070, 1 IL2075, 1 IL2067)
  builds a descriptor from a `Type` and resolves the options of a provider from a
  `Type`, and both parameters have to name the members they read;
- `TinyComponentBase.cs` (1 IL2070, 2 IL2075) reads the public properties of a
  component type;
- `Feed/BlockPageBase.cs` (2 IL2075) reads the public and the non-public methods
  of a base type;
- `DataGrid/DataGridColumn.razor` (1 IL2075) reads a property of a type it holds;
- `src/blocks` reads the members of the descriptor and the entity types at run
  time: `Session/DynamicBlock.razor.cs` (9 IL2075),
  `Session/DynamicNodeBlock.razor.cs` (6 IL2075),
  `Session/HttpDynamicNodeRuntime.cs` (1 IL2075),
  `Session/DynamicBlockModels.cs` (2 IL2070),
  `Session/SessionContextBlock.razor.cs` (1 IL2070),
  `Session/SessionContextBlockOverlayContent.razor.cs` (1 IL2075).

The fix shape is the annotation of the source of the value: a
`DynamicallyAccessedMembers` annotation on the parameter, on the field or on the
property that carries the `Type`, so the members that the code reads are kept.

### The unrecognized type name and the generated code — IL2057, IL2111, 4 warnings

- `Showcode/StoryCard.razor` (2 IL2057) resolves a type by name with
  `Type.GetType(typeName)`, and the trimmer cannot know that the type is present;
- the two generated files of the Razor source generator carry one IL2111 each,
  because the generated code hands a `Type` to a member that expects an annotated
  one. The generated code is not hand written, so the fix belongs to the
  annotation of the member it calls, not to the generated file.

### The validation of the model — 2 of the IL2026 warnings

`DataForm/DataForm.razor.cs` (2 IL2026) constructs a
`System.ComponentModel.DataAnnotations.ValidationContext` and calls
`Validator.TryValidateObject`. The runtime reads the type of the instance by
reflection to resolve the display name, so a validation context needs an explicit
display name to stay trim-safe.
